# ТЗ: Career Advisor

## Цель и аудитория

Помочь одному кандидату подготовить содержательный, проверяемый отклик на конкретную вакансию: адаптированное резюме, письмо и сведения о работодателе. Первая версия предназначена для личного локального использования и демонстрации в портфолио.

Продукт не обещает найм, не принимает решение за работодателя и не отправляет отклики автоматически.

## Основной пользовательский путь

1. Создать независимый отклик либо открыть синтетическое демо.
2. Загрузить текстовый PDF или вставить резюме. Проверить и подтвердить факты.
3. Вставить вакансию либо получить её по публичной ссылке. Подтвердить требования и обязательность.
4. Получить сравнение по каждому требованию. Исправить сомнительную строку вручную либо уточнить опыт.
5. Ответить на уточнения или пропустить их. Новые ответы добавлять в профиль только после подтверждения.
6. Получить адаптацию. Рассмотреть «до/после», причины и основания; принять или отклонить каждую правку.
7. Собрать и отредактировать резюме, подтвердить итог и скачать PDF/DOCX.
8. Подготовить, проверить и подтвердить письмо. Скачать TXT.
9. Исследовать компанию: прочитать отчёт, основания, неизвестное и вопросы для интервью; скачать Markdown.
10. Вернуться к отклику позже или восстановить предыдущую версию.

## Функциональные требования

| Область | Критерий приёмки |
| --- | --- |
| Демо | Создаётся отдельный отклик на вымышленных данных без обращения к AI и поиску |
| Факты | Неподтверждённые предложения без основания показаны отдельно и не используются в анализе |
| Вакансия | У каждого требования есть цитата; обязательность не выводится только из упоминания навыка |
| Сравнение | Каждое требование получает отдельную строку; отсутствие данных не приравнивается к отсутствию навыка |
| Ошибки AI | Неверная ссылка в одной строке не уничтожает остальные корректные результаты |
| Условия | График и формат работы подтверждаются кандидатом, а не предполагаются по резюме |
| Адаптация | Только известные факты-основания; решения по правкам сохраняются; отклонённая правка не попадает в сборку |
| Изменение данных | Зависимые текущие документы сбрасываются; прошлые снимки остаются в истории |
| Версии | Устаревшая команда из другой вкладки получает конфликт и не перезаписывает новое состояние |
| Экспорт | PDF/DOCX и письмо доступны после подтверждения; отчёт компании — после появления содержательных выводов |
| Поиск | Материалы проверяются на связь с работодателем, очищаются; у утверждений отчёта есть фрагменты-основания |
| Сбой отчёта | Причина и следующее действие понятны; полученные источники сохраняются; нет ложного статуса готовности |
| Приватность | Ключей нет в интерфейсе; профиль не включается в исследование компании; база и документы не коммитятся |

## Нефункциональные требования текущей версии

- Локальный адрес 127.0.0.1, один процесс сервера, SQLite без внешнего сервиса.
- Проверенное окружение — Python 3.14/macOS. Нет заявления о поддержке Windows.
- PDF: максимум 10 МБ/20 страниц, текстовый слой, ограниченный отдельный процесс чтения.
- Подготовленная демонстрация доступна без API-ключей. Настоящие запросы запускаются явно.
- Ошибки не раскрывают ключи и содержимое резюме в журналах.
- Не повторять платные операции автоматически после сбоя.
- Сохранять читаемость интерфейса на настольном и мобильном экране.

## Осознанно вне MVP

Регистрация, несколько пользователей, публичное размещение, OCR, сбор вакансий в промышленных масштабах, автоматическая отправка откликов, собственное обучение модели, гарантия трудоустройства и численный рейтинг ATS.

## Проверка изменений вдвоём

1. Сформулировать ожидаемое пользовательское поведение до изменения кода.
2. Проверить сценарий на синтетическом отклике. Настоящие резюме не использовать как тестовые фикстуры.
3. Запустить локальные тесты. При изменении PDF/DOCX открыть и проверить сам документ.
4. Для запроса к внешнему сервису отдельно определить лимит и данные; не считать успешный мок доказательством доступности провайдера.
5. В описании изменения указать, что проверено, и оставшиеся ограничения.

Следующие улучшения выбираются по наблюдаемым проблемам: качество подбора источников, сохранение смысла при адаптации, удобство просмотра оснований и воспроизводимость установки. Добавление нового агента или технологии само по себе не является критерием готовности.
